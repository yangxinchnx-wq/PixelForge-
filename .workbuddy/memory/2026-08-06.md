## 用户架构决策咨询：导入 3D 模型做视频是否可行

### 用户场景
用户做视频（PixelForge 是 2D 视觉引擎 + 视频时间轴），现在想"导入 3D 模型 → 渲染成视频"，问可行性。

### 架构边界审查
查看 `src/shared/types.ts` 第 117-124 行 Opcode 枚举：
- SOLID_COLOR=0, LINEAR_GRADIENT=1, NOISE=2, BLEND=3, CIRCLE_SHAPE=4, IMAGE_TEXTURE=5
- 当前无 3D/Mesh/Model 相关 Opcode

查看 `src/compiler/ir/renderIR.ts` 静态边界硬约束（6 条）：
- Layer/Region/Effect 不出现 time/frame/phase/animationPhase
- Render IR 不允许跨帧资源引用
- Render IR 不允许携带可执行语义（无脚本/DSL/lambda）

这意味着 3D 模型作为"Layer Source"接入是符合现有架构的（跟 IMAGE_TEXTURE 同级别），
但不能把 3D 场景逻辑塞进 Render IR。

### 三种可行方案
1. **嵌入式 3D Pass（轻量自研）** - 新增 Opcode.MODEL_3D，扩展 region_eval.wgsl，工作量中等
2. **集成 Orillusion 作为子引擎** - Orillusion 渲染到纹理 → 作为 IMAGE_TEXTURE 注入，工作量小但耦合
3. **离线 3D 渲染 + 视频导入** - 用 Blender/Orillusion 离线渲染 MP4 → 作为视频片段导入，工作量最小

推荐：方案 2（集成 Orillusion 作为子引擎）作为起步，方案 1（自研轻量 3D Pass）作为长期演进。

## 关键定位校准（用户纠正了我的理解）

## UAV Split 接入真实渲染管线(evaluator) + 通路测试(收尾)

### 用户要求

### 关键发现(真实 WebGPU 正确性,此前模块未覆盖)
1. `effect_post.wgsl` 唯一 `read_write` 存储纹理是 `outputTex: texture_storage_2d<rgba8unorm, read_write>`(binding 1)。UAV Split 把它拆成:原纹理变只写(binding 1) + 只读副本 `outputTex_readOnly`(binding 5)。
2. `shaderCodeModifier` 改写后 **只读副本声明没有 @binding** → WebGPU `layout:'auto'` 会校验失败。必须接入层为副本注入显式 `@group(0) @binding(5)`。
3. `GpuUavSplitBackend.createReadOnlyTexture` 原用 `TEXTURE_BINDING`,但只读副本以 `texture_storage_2d<..., read>` 形式绑定,必须是 **STORAGE_BINDING**。已修正为 `STORAGE_BINDING | COPY_DST`。
4. 复制必须 **逐帧** 录制:图层 pass 每帧覆盖 output.texture,故只读副本内容需在效果 pass 前用 `recordUavCopy` 从 output.texture 刷新,不能依赖 applyUavSplit 的一次性复制。
5. `output.texture`(output.ts 创建)已含 `COPY_SRC`,满足复制源要求。
6. `GpuUavSplitBackend` 构造函数原为 `GPUDevice`,改为 `RuntimeDeviceHandle`(evaluator 只有该抽象),方法签名兼容。

- `src/runtime/uav/integration.ts`(新建):`prepareEffectUavSplit(device,effectShaderSource,output,backend)`,分析→规划→改写→为只读副本注入 @binding(5)→创建只读副本纹理一次。不含复制(复制由调用方逐帧做)。导出 `EFFECT_READ_ONLY_BINDING = 5`。
