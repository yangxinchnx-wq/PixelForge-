第二部分：第三套系统是否存在？ 确认存在
✓
第三套系统确实存在，且实际上包含两个子系统

经过代码搜索验证，"第三套时间轴"不仅存在，而且实际上是 两个独立的关键帧动画系统，它们分别绑定不同的 Store、使用不同的时间单位、服务于不同的渲染管线：

  • 系统 3A：帧级参数动画 — 基于 frame 整数，绑定 RenderIR.layers
  • 系统 3B：秒级动画系统 — 基于 time 秒（浮点），绑定 GraphNode + MaterialNode

两个子系统共享 src/components/editor/timeline/ 目录下的部分 UI 组件，但数据模型、Store、求值器完全独立。

系统 3A：帧级参数动画

Frame-based Parameter Animation · Step 29 早期
Store useTimelineStore('timeline')
Store 位置 src/stores/timeline.ts
时间单位 frame 整数（0~299）· fps 默认 60
数据模型 ParameterTrack → Keyframe（frame + value 0~1 + easing）
绑定目标 RenderIR.layers[*].id + layer.params
缓动类型 linear · ease（smoothstep）· hold
求值器 src/editor/timeline/evaluator.ts
播放器 src/editor/timeline/player.ts → rAF 循环 → ValuePatch → runtime
类型定义 src/editor/timeline/types.ts
UI 组件 components/editor/Timeline.vue + ParameterTrack.vue + CurveCanvas.vue
被引用处 runtime/engine.ts · runtime/engineScheduled.ts · project/serializer.ts · project/projectStore.ts · runtime/frameScheduler.test.ts
默认轨道 4 条预设轨道（红圆半径/蓝圆半径/绿圆半径/底色明度）· 300 帧 · 60fps

系统 3B：秒级动画系统

Time-based Animation System · Step 29.2+
Store useAnimationStore('animation')
Store 位置 src/animation/timeline.ts
时间单位 time 秒（浮点）· fps 默认 60 · duration 默认 10s
数据模型 AnimationTrack → Keyframe（time + value + interpolation + cp1/cp2）
绑定目标 targetKind: graph / material / runtime → nodeId + property
缓动类型 linear · bezier（三次贝塞尔 + cp1/cp2 控制点）· step
动画模式 KEYFRAME · EXPRESSION（JS 表达式）· PHYSICS（预留）
求值器 src/animation/evaluator.ts（独立于 3A）
播放器 src/animation/player.ts + scheduler.ts + uniformUpdater.ts
GPU 集成 有 · UniformUpdate → GPUBuffer 直接写入
UI 组件 AnimationTimeline.vue + AnimationRuler/Playhead/Track/Keyframe
绑定模块 src/animation/binding.ts + mapper.ts + curve.ts
输入驱动 src/animation/drivers/inputDriver.ts（传感器/摄像头/MIDI → 动画）

结论

1. 系统1（Core Timeline）和系统2（ProTimeline）是两套并行的视频编辑时间轴，Core 是早期基础版，Pro 是 Step 31.x 的专业增强版。

2. 第三套系统确实存在，且本身分为 3A（帧级参数动画）和 3B（秒级动画系统）两个子系统。

3. 3A 和 3B 共享 components/editor/timeline/ 下的 UI 组件目录，但 Store、数据模型、求值器、播放器完全独立。

4. 四套系统共涉及 ~100+ 个文件，其中存在大量功能重叠和数据模型不一致，有统一整合的空间。
